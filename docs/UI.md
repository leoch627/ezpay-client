# 本地面板（浏览器）

网关自带一个单页面板，`go:embed` 打进二进制，打开浏览器即可用。
**没有额外运行时依赖**，不需要装 WebView2 / WinUI / .NET。

---

## 打开

```
http://127.0.0.1:29731/
```

端口被占用时网关会自动顺延（29732、29733…），启动日志与页面左下角都会显示**实际**地址：

```
[http] 面板监听 http://127.0.0.1:29732
```

五个页面可以直接用 hash 定位（方便收藏）：

| 页面 | 地址 |
|---|---|
| 概览 | `/#overview` |
| 微信账号 | `/#account` |
| 收款记录 | `/#records` |
| 日志 | `/#logs` |
| 设置 | `/#settings` |

---

## 一、概览

| 指标 | 含义 | 数据来源 |
|---|---|---|
| 识别收款 | 累计入库的收款事件数 | `queue` 表 |
| 上报成功 | 累计上报成功数（state=done） | `queue` 表 |
| 待发送 | pending + paused | `queue` 表 |

> 这三个数**来自数据库**，网关重启不丢。
> 不要和「诊断」里的 Hook 计数器混淆——那个只统计当前微信进程生命周期。

下面的「上游收款站」显示当前配置的地址与商户 ID，可以点「测试连接」验证。

「最近活动」是最近 10 条事件流（收款 / 上报 / 通道 / 设置 / 错误）。

---

## 二、微信账号

| 区块 | 内容 |
|---|---|
| 账号卡 | 当前收款账号 `wxid_xxx` + Hook 状态徽章 |
| 账户 | 微信程序路径、**版本号**、进程 PID、最后活动时间 |
| 上报 | **通道 ID**（按账号绑定）、**固定金额收款项**数量 |
| 诊断 | Hook 状态、命中的特征码、捕获/识别计数、去重丢弃数 |

### 2.1 版本号怎么来的

读的是 `Weixin.exe` 的 **PE 版本资源**（`GetFileVersionInfo`），结果形如 `4.1.12.53`。

**不要**去读注册表里的 `Version` DWORD 做位运算——那是微信自定义打包的编码：

| 原始值 | 真实版本 | 若按 `major<<24\|minor<<16\|...` 解 |
|---|---|---|
| `0xF254200D` | 4.1.48.13 | 242.84.32.13 ✗ |
| `0xF2541C35` | 4.1.12.53 | 242.84.28.53 ✗ |

逆向包里也没解出规律（见 `scripts/decode_wechat_version.py`）。文件版本是标准格式，永远正确。

### 2.2 绑定通道 ID

点「绑定」弹窗，语义与真实程序一致：

```
wechat:wxid_jalj9ys3nz8u12  ->  "6552"
```

- 留空保存 = **解绑**，上报时走上游默认通道
- 存到 `data/account_channels.json`，格式与真实程序完全相同
- 只允许字母、数字、`-`、`_`，最长 64 字符

上报时 `channelId` 会带进 body（未绑定则不带）。

### 2.3 固定金额收款项

点「管理」打开弹窗：

- 列表按金额升序，可逐条删除
- 新增：填名称（≤32 字）+ 金额（元），回车或点「添加」
- 金额**按元输入、按分存储**（`priceCents`），超过两位小数直接截断，绝不四舍五入
- 存到 `data/payment_codes.json`

## 三、收款记录

队列最近 100 条，四列：金额 / 状态 / 结果 / 重试次数。

| 状态 | 徽章颜色 | 含义 |
|---|---|---|
| `done` | 绿 | 上报成功，上游已确认 |
| `failed` | 红 | 终态失败（未匹配订单、ts skew、bad amount） |
| `paused` | 黄 | 密钥不对，整个队列暂停，需人工修 |
| `pending` | 灰 | 等待发送 / 退避重试中 |

「恢复暂停项」把 paused 全部转回 pending 并立刻重试——修好密钥后点一下即可，不用重启。

---

## 四、日志

实时事件流（2 秒刷新），等宽字体。

- 可按「仅错误 / 仅警告」过滤
- 「自动滚动」默认开，滚到底跟随最新
- 每行格式：`时间  级别  模块  内容`

事件来自 `events` 表（只保留最近 2000 条，自动清理）。

## 五、设置

### 5.1 上游收款站

| 字段 | 说明 |
|---|---|
| 地址 | 你的收款站根地址，如 `https://pay.example.com`。**末尾斜杠自动去掉** |
| 商户 ID | 上报必带，不能为空 |
| 商户密钥 | 用于 HMAC 签名。**留空表示不修改已保存的** |

密钥的处理是这个面板的重点：

1. 你填的明文密钥 **不会落盘**——提交时后端用 Windows DPAPI 加密，存进 `protectedMerchantSecret`
2. `config.json` 里的 `reportToken` 保存后立刻被清空
3. API 返回的永远是打码值（`my-s****c123`）
4. 重启时从 DPAPI 密文解回内存供签名使用

```
config.json（保存后）
{
  "merchantId": "10059",
  "reportToken": "",                                    ← 空
  "protectedMerchantSecret": "enc:v1:AQAAANCMnd8BFdERjHoAwE..."  ← DPAPI 密文
}
```

**代价**：DPAPI 作用域是 CurrentUser，换机器 / 换用户后解不开，需要重新填密钥。
这正是它比明文安全的原因。

### 5.2 运行

| 字段 | 说明 |
|---|---|
| 监听地址 | 面板与事件接收端口，默认 `127.0.0.1:29731` |
| 上报超时 | **最低 45 秒**。上游回调最长可拖到 33 秒，低于 45 会大量误判超时 |
| 事件来源 | `inject`（注入）/ `uia`（读窗口）/ `manual`（仅外部事件） |

保存后立即生效，无需重启。

## 六、为什么不用 WinUI

原本做了一个 WinUI 3 版本，在这台机器上会遇到：

- `XamlCompiler` 在 Pass1 阶段退出码 1，不给任何诊断，清空 `obj/bin` 也无法恢复
- 改成纯代码构建（不用 XAML）后能编译，但进程启动约 8 秒后必定静默退出（`0xC000027B`），
  无托管异常、关掉轮询也照退；`SelfContained` 与框架依赖两种模式都试过

浏览器面板没有这些问题，而且用户零安装。

WinUI 源码保留在 `ui/WxPayClientUI/`（`App.cs` / `MainWindow.cs` / `Ui.cs` / `Dialogs/`），
如需继续排查可以直接 `dotnet build -c Release -p:Platform=x64`。
